# AGENTS.md — 手沖咖啡風味科學 LLM Wiki 指南

本檔案為本知識庫的核心運作規範與 Schema。本專案以 Andrej Karpathy 的 LLM Wiki 模式為基礎，專門為「手沖咖啡風味科學」量身打造。

---

## 1. 核心定位與內容原則

- **目標優先序**：
  1. 🥇 **教材與簡報產出庫（Education / Presentation）**：知識模組化、論述清晰易懂、具備教學說服力與簡報轉化價值。
  2. 🥈 **實戰沖煮與參數診斷（Dial-in / Troubleshooting）**：具備強大可操作性、明確的風味診斷樹與參數調整方向。
  3. 🥉 **科學文獻與理論編譯（Research & Compounding）**：作為底層理論支撐與科學依據，打破流言與玄學。
- **內容黃金比例（70 / 30 原則）**：
  - **70% 實用風味對照與應用**：感官體驗、風味特徵、萃取變因對比、新手與進階沖煮指南、常見風味問題診斷。
  - **30% 底層科學原理解析**：物理流體力學、化學萃取溶解度、熱傳導、有機酸與芳香物質降解機制。

---

## 2. 知識庫三層架構

1. **原始文獻層 (`raw/`)**：
   - 存放文章、論文摘要、書籍筆記、杯測紀錄。
   - **唯讀原則**：LLM 僅能讀取與引用，不可篡改原始來源。
2. **知識庫本體層 (`wiki/`)**：
   - 由 LLM 全權建立與維護的 Markdown 文件網絡。
   - 採用 **Obsidian 雙向連結語法 `[[Page-Name]]`**。
   - 具備高密度相互參照（Cross-referencing），任何新資料進入皆需跨頁面更新。
3. **規範與運作層 (`AGENTS.md`)**：
   - 即本文件，指導 LLM 執行的 SOP、目錄分類標準與維護守則。

## 3. 目錄結構與分類職責 (Taxonomy)

```text
LLM Wiki/
├── raw/                          # 原始資料庫（唯讀來源）
├── wiki/
│   ├── curriculum/               # 課程模組與簡報藍圖（主題教學、章節教案、核心概念演講稿）
│   ├── troubleshooting/          # 實戰風味診斷矩陣（過酸、過苦、澀感、空泛等校正指南）
│   ├── variables/                # 手沖四大關鍵變因（水溫、研磨度、粉水比、時間與流速）
│   ├── equipment/                # 濾杯幾何與沖煮器具（V60、蛋糕濾杯、梯形濾杯、流速對比）
│   ├── processing-and-roast/     # 處理法與烘焙度（水洗/日曬/蜜處理、淺焙/中焙/深焙）
│   ├── chemistry/                # 化學與萃取物質（綠原酸、檸檬酸、蘋果酸、美拉德產物、TDS/EY%）
│   ├── sensory/                  # 感官與風味表現（酸質結構、醇厚度 Body、甜感、乾淨度、苦澀成因）
│   ├── sources/                  # 針對 raw/ 文獻的萃取筆記與摘要頁面
│   ├── index.md                  # 全庫總目錄（內容導向，依類別維護）
│   └── log.md                    # 時間序列日誌（紀錄每次 Ingest / Query / Lint）
├── picture/                      # 簡報與圖解資源庫（目前保留，由使用者後續規劃）
└── AGENTS.md                     # 本規範文件
```

## 一、 實用風味對照與操作指南（70% 實踐）

- **感官特徵與風味表現**：具體形容詞（如明亮柑橘酸、焦糖甜感、圓潤醇厚度）。
- **實戰對照表**：使用 Markdown 表格清晰對比不同條件下的風味差異。
- **新手操作與調整建議**：具體數值區間（粉水比、水溫、研磨顆粒）。

---

## 二、 底層科學原理解析（30% 科學）

- **物理/化學機制**：物質溶解速率、流體流速、熱力學影響、化合物轉換。
- **金杯理論/數據依據**：TDS（濃度 %）、EY（萃取率 %）、微米（μm）等定量依據。
- **常見迷思破解**：澄清坊間經驗論與科學實證的落差。

## 5. 三大核心運作流程 (Operations)

### 流程一：攝入文獻 (Ingest)
1. **讀取來源**：閱讀 `raw/` 中的新文件，解析其中的核心主張、數據與實驗條件。
2. **建立文獻筆記**：在 `wiki/sources/` 建立對應的來源摘要頁，紀錄主要論點與引用。
3. **橫向分發與更新 (Fan-out)**：
   - 檢查並更新 `variables/`、`processing-and-roast/`、`equipment/` 等相關實體頁面。
   - 若有新觀點或衝突論點，在現有頁面中以「觀點討論」形式增補，不直接抹除歷史紀錄。
4. **同步目錄與日誌**：
   - 更新 `wiki/index.md` 中的分類與一覽清單。
   - 在 `wiki/log.md` 新增標準格式條目：
     `## [YYYY-MM-DD] ingest | 文獻標題`。

### 流程二：查詢與教學問答 (Query)
1. **檢索與綜合**：先由 `wiki/index.md` 尋找關聯頁面，綜合提取風味對照與科學原理。
2. **回答結構**：優先給出簡報級的「白話金句 + 對照表格 + 實踐步驟」，隨後補充科學原理。
3. **回饋沉澱 (Compounding)**：
   - 若使用者提出深刻的探討、產生了新的沖煮方案或教學大綱，主動將精華沉澱回 `wiki/curriculum/` 或 `wiki/troubleshooting/` 成為新頁面。

### 流程三：知識庫巡檢 (Lint)
定期檢查維護知識庫品質：
- **孤島頁面 (Orphan Pages)**：檢查是否有未被 `index.md` 或其他頁面引用的孤立檔案。
- **矛盾檢驗**：檢查不同處理法或烘焙度對風味影響的描述是否存在前後邏輯衝突。
- **連結完整度**：確保所有 `[[Wiki-Link]]` 指向的目標頁面皆已存在或有建立計畫。
- **70/30 比例維持**：確保內容不偏向晦澀論文堆砌，亦不淪為缺乏原理的口訣。
